1. **BLOCKER** — [src/lib/actions/evaluations.ts:385](/Users/mohsin/Github/safemolt/src/lib/actions/evaluations.ts:385)  
   `startEvaluationWithEffect` can create or expire a certification job after the conditional start operation did not start the registration. For example, a concurrent submit can change the registration from `registered` to `completed` before the start CAS. The CAS then returns no job. Lines 385–403 find no existing job and call `createCertificationJob` for the completed registration. This emits no `evaluation.started` event and breaks the required single conditional operation. A repeated start can also expire and replace a job.  
   **Minimal fix:** Remove the fallback mutations from this action. The conditional store operation must be the only operation that can create the first job or challenge. A call that did not win the start CAS can only read and return an existing effect; it must not create, expire, or replace one.

2. **MAJOR** — [src/app/api/v1/evaluations/[id]/submit/route.ts:80](/Users/mohsin/Github/safemolt/src/app/api/v1/evaluations/[id]/submit/route.ts:80)  
   The certification branch is not a parse → action → render adapter. It directly expires jobs at line 40 and directly performs the agent-visible transcript mutation at line 86. It also owns the job authorization and refusal classification. A later tool or route cannot share this decision, and this Tier-1 write remains outside the action boundary.  
   **Minimal fix:** Move certification transcript validation, authorization, expiry classification, and `submitCertificationTranscript` into an evaluation action. Let the route parse the body, call that action, schedule judging after an accepted result, and render the existing response.

3. **MAJOR** — [src/app/api/v1/agents/claim/route.ts:32](/Users/mohsin/Github/safemolt/src/app/api/v1/agents/claim/route.ts:32)  
   The Cognito claim adapter still decides `not_found` and `already_claimed` from a pre-read at lines 32–43. It can return without calling the action, although the action correctly classifies from `agentExists` and `claimed` at [src/lib/actions/agents.ts:272](/Users/mohsin/Github/safemolt/src/lib/actions/agents.ts:272). It also renders the success response from the old pre-read instead of `claimed.data.agent`. For example, a concurrent agent rename can make the claim succeed while the response reports the old name.  
   **Minimal fix:** Call `claimAgentWithCognito` after parsing and authentication. Render its flag-based refusal and use the returned agent for the success body. Do not use the pre-read as a refusal decision.
