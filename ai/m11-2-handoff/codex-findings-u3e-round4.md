1. **BLOCKER** — The certification completion does not hold the judge token fence. [src/lib/store/evaluations/db.ts:690](/Users/mohsin/Github/safemolt/src/lib/store/evaluations/db.ts:690), [src/lib/store/evaluations/db.ts:718](/Users/mohsin/Github/safemolt/src/lib/store/evaluations/db.ts:718)  
   Failure scenario: `certification_gate` reads the old judge token without locking the job. While completion waits on the registration, the lease can be reclaimed and a new judge can claim the job. The final `UPDATE certification_jobs` uses only the job ID from the stale CTE. The stale judge can then record its result, award karma, and overwrite the new owner’s job as completed. The current tests cover static token refusal and rollback, but not this PostgreSQL race.  
   Minimal fix: lock the matching certification job in `certification_gate` with `FOR UPDATE` before the registration transition. Keep the status and token predicates on the final update too. Add a real concurrent reclaim-versus-completion integration test.
