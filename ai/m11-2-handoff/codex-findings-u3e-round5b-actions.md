1. **MAJOR — Flow-specific start writes are not coupled to `evaluation.started`.**  
   [evaluations.ts](/Users/mohsin/Github/safemolt/src/lib/actions/evaluations.ts:343) performs the registration CAS first. It then creates the PoAW challenge or certification job at [line 351](/Users/mohsin/Github/safemolt/src/lib/actions/evaluations.ts:351) and [line 373](/Users/mohsin/Github/safemolt/src/lib/actions/evaluations.ts:373). A repeated PoAW start has `started === false`, emits no `evaluation.started`, but still inserts a new durable challenge. Also, if the first request emits the event and then challenge creation fails, the retry inserts the challenge without an event. The same gap applies to a certification job. Minimal fix: make the CAS and its flow-specific durable write one conditional transaction, with the event gated on the complete operation. If that change is deferred, do not claim that these writes ride `evaluation.started`; record them as uncovered Tier-1 writes.

2. **MAJOR — Self-serve executor errors have an unapproved behavior and wire change.**  
   [evaluations.ts](/Users/mohsin/Github/safemolt/src/lib/actions/evaluations.ts:632) now converts any executor `result.error` into a 400 refusal before completion. Before u3e, the self-serve route saved the executor result and returned the normal 200 result body with its `error` field. For example, an executor result `{passed:false, error:"invalid"}` now writes no terminal result and permits a different retry. The characterization suite does not pin this branch, and it is not listed as a planned behavior change. Minimal fix: preserve the previous self-serve behavior by passing the result to `completeEvaluation`; or explicitly approve the change and add exact route characterization for it.

3. **MAJOR — The already-vetted rule is still an adapter pre-read and has a race.**  
   [vetting/start/route.ts](/Users/mohsin/Github/safemolt/src/app/api/v1/agents/vetting/start/route.ts:25) decides `already_vetted` before it calls the action. [startVetting](/Users/mohsin/Github/safemolt/src/lib/actions/agents.ts:312) always creates a challenge and does not recheck current eligibility. If vetting completes after authentication supplies the stale agent object but before `startVetting` inserts, this request creates a new challenge and `agent.vetting_started` for an already-vetted agent. A sequential request writes nothing. Minimal fix: make the store operation conditionally insert only while the agent is not vetted, return decisive outcome flags, and let the action classify `already_vetted`. The route must only render that result.

4. **MAJOR — Claim actions collapse decisive “missing” and “already claimed” outcomes.**  
   [claimAgentWithCognito](/Users/mohsin/Github/safemolt/src/lib/actions/agents.ts:269) and [claimAgentWithX](/Users/mohsin/Github/safemolt/src/lib/actions/agents.ts:296) map every null store result to `already_claimed`. The route pre-reads provide the initial 404, but they are stale after the external X checks or any other await. If the agent is deleted or its token stops resolving in that window, the decisive write matches no agent and the action reports “already claimed.” Minimal fix: have each decisive store operation return classified flags such as `agent_exists` and `claimed`, then map those flags in the action. Do not reconstruct the refusal from the route pre-read.

5. **MAJOR — The claimed adapter and authorization evidence is incomplete.**  
   The characterization header claims coverage for eight routes and five tools at [lines 5–16](/Users/mohsin/Github/safemolt/src/__tests__/api/v1/m11-2-u3e-evaluations-characterization.test.ts:5), but its route imports at [lines 38–46](/Users/mohsin/Github/safemolt/src/__tests__/api/v1/m11-2-u3e-evaluations-characterization.test.ts:38) omit both claim routes and the vetting-complete route. The negative tests also do not deliver the required full C2 matrix through both adapters: self-proctoring is route-only at [line 459](/Users/mohsin/Github/safemolt/src/__tests__/api/v1/m11-2-u3e-evaluations-characterization.test.ts:459), nonparticipant messaging is route-only at [line 638](/Users/mohsin/Github/safemolt/src/__tests__/api/v1/m11-2-u3e-evaluations-characterization.test.ts:638), and there are no route-and-tool pairs for mismatched IDs, ended sessions, or cancelled registrations. A tool-only authorization regression in these branches can pass all u3e tests. Minimal fix: add table-driven parity cases that run every required denial through the real route and real tool, and add exact characterization for claim, verify, and vetting-complete responses.

6. **MINOR — Two “memory race” tests do not create real contention.**  
   [evaluations.test.ts](/Users/mohsin/Github/safemolt/src/__tests__/lib/actions/evaluations.test.ts:263) and [complete-vetting-memory.test.ts](/Users/mohsin/Github/safemolt/src/__tests__/lib/store/agents/complete-vetting-memory.test.ts:135) use `Promise.all`, but the memory mutation’s decisive section is synchronous. The first call completes that section before the second call can enter it. These tests prove repeated-call behavior, not a race. The Postgres suite does use contention helpers, so this does not remove DB race evidence. Minimal fix: rename these as sequential/idempotency parity tests, or add a controlled barrier at a real asynchronous eligibility boundary if memory contention must be tested.
